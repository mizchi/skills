# TypeScript の型安全性を高めるためのベストプラクティス

TypeScript は JavaScript に静的型付けを足した言語です。採用は進んでいます。型安全性を高めるやり方をいくつか挙げます。

## 型安全性とは何か

型安全性は、プログラムを実行する前に型の不整合を見つけられる性質です。型安全性の高いコードは保守しやすくなります。型安全性を高めると、実行時エラーを減らせます。

型安全性はチーム開発でも効きます。型情報がドキュメントとして働くので、新しいメンバーがコードベースを読みやすくなります。

## strict モードを有効にする

`tsconfig.json` で `strict` を有効にします。

```json
{
  "compilerOptions": {
    "strict": true
  }
}
```

strict を有効にすると、型チェックが厳しくなります。潜在的なバグを早く見つけられます。

## any 型の使用を避ける

`any` は型チェックを無効にするので、使わないほうがいいです。代わりに `unknown` を使います。`unknown` なら型の絞り込みが強制されます。

`any` を検出する ESLint ルールを入れる手もあります。ルールを決めておけば、チームで型の運用が揃います。

## 型推論を活用する

TypeScript の型推論は強力です。明示的な型注釈を書きすぎると保守性が下がります。自分は推論に任せられるところは任せる派です。

型推論に任せると、記述量が減って型安全性は保てます。

## ユーティリティ型を使いこなす

TypeScript には `Partial`、`Required`、`Pick`、`Omit` といったユーティリティ型があります。既存の型から新しい型を導けます。記述量が減り、型の一貫性も保てます。

型定義が重複するとバグの元になります。ユーティリティ型で型定義を一箇所にまとめておくといいです。

## おわり

やることは 4 つです。

- strict モードを有効にする
- `any` の使用を避ける
- 型推論を活用する
- ユーティリティ型を使いこなす

型安全性はすぐには上がりませんが、段々に入れていけばコードベースの質は上がります。
